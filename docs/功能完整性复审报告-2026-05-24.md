## 发现的问题

### P1 - `stop_on_damage: false` 实际无法让损坏机器继续工作

位置：
- `src/main/resources/machine-damage.yml:15`
- `src/main/java/io/github/thebusybiscuit/slimefun4/core/services/MachineDamageService.java:203`
- `src/main/java/io/github/thebusybiscuit/slimefun4/implementation/tasks/TickerTask.java:243`
- `src/main/java/me/mrCookieSlime/Slimefun/Objects/SlimefunItem/abstractItems/AContainer.java:374`
- `src/main/java/io/github/thebusybiscuit/slimefun4/implementation/listeners/SlimefunItemInteractListener.java:124`

`stop_on_damage` 只控制损坏时是否写入 `machine_damage_enabled=false`，但运行链路里多个地方仍然只要 `isMachineDamaged(data)` 为 true 就直接跳过 ticker 或阻止交互。因此即使管理员把 `stop_on_damage` 配成 false，机器损坏后仍会停机并无法正常交互。

影响：配置项语义与实际行为不一致，管理员无法配置“损坏但不停机”的策略。

实施：以"删除配置项"方式解决（损坏=停机不可逆）。

### P1 - 电网自调度仍在异步线程读写运行态和方块数据

位置：
- `src/main/java/io/github/thebusybiscuit/slimefun4/core/networks/energy/EnergyNet.java:2350`
- `src/main/java/io/github/thebusybiscuit/slimefun4/core/networks/energy/EnergyNet.java:2377`
- `src/main/java/io/github/thebusybiscuit/slimefun4/core/networks/energy/EnergyNet.java:2381`
- `src/main/java/io/github/thebusybiscuit/slimefun4/core/networks/energy/EnergyNet.java:2770`

`scheduleSelfTick()` 使用 `runTaskTimerAsynchronously` 驱动 `tickSelf()`，而 `tickSelf()` 会执行能量传输、计数器写入、连接器老化以及总电量统计。与此同时，放置/破坏/限电器设置会通过主线程或聊天回调触发 `markDirty()`、`setConnectorLimit()` 等逻辑修改同一批网络状态。

影响：仍存在并发修改、半初始化状态读写和 Bukkit/存储对象跨线程访问风险。当前构建无法覆盖这类运行时问题。

建议：将 Bukkit/方块/存储访问和网络快照采集放在主线程或统一串行入口，异步线程只处理纯路径计算。

方案:详细分析此问题 并且给出详细方案
### P2 - 登录损坏提醒只覆盖已加载数据

位置：
- `src/main/java/io/github/thebusybiscuit/slimefun4/implementation/listeners/MachineDamageNotificationListener.java:61`
- `src/main/java/com/xzavier0722/mc/plugin/slimefun4/storage/controller/BlockDataController.java:1236`
- `src/main/java/com/xzavier0722/mc/plugin/slimefun4/storage/controller/BlockDataController.java:1241`

当前登录提醒遍历 `getAllLoadedData()`，该集合只包含已加载区块数据和 `loadedUniversalData`。未加载区块中的损坏机器、未加载的通用方块数据不会被提醒。

影响：玩家登录时可能看不到自己离线区域或未加载区域里的损坏机器/损坏连接器，只能靠靠近加载或手动排查发现。

建议：存储层提供按 owner 和损坏字段查询的 API，并维护损坏索引。
实行建议
### P3 - 即时损坏通知的默认世界名映射存在拼写偏差

位置：
- `src/main/java/io/github/thebusybiscuit/slimefun4/core/services/MachineDamageService.java:33`
- `src/main/java/io/github/thebusybiscuit/slimefun4/core/services/MachineDamageService.java:35`
- `src/main/java/io/github/thebusybiscuit/slimefun4/core/services/MachineDamageService.java:37`

`MachineDamageService#getFriendlyWorldName()` 使用 `worlds`、`worlds_nether`、`worlds_the_end`，而登录提醒里的映射使用常见的 `world`、`world_nether`、`world_the_end`。

影响：机器损坏即时通知中，默认世界名不会被本地化成“主世界/地狱/末地”，表现为原始 world 名称。该问题不影响核心逻辑，但会造成提示体验不一致。

建议：统一两处世界名映射，抽成共享工具方法，并支持配置文件覆盖。
实行建议
