# 电动洗矿机产物槽满时暂停设计

## 1. 背景

电动洗矿机的产物可能来自多个随机结果，当前 `findNextRecipe(...)` 使用本次随机产物调用 `menu.fits(...)` 判断输出空间喵~

当两个产物槽已经分别放置了不同物品时，如果本次随机结果恰好能够与其中一格堆叠，机器仍会启动下一次加工喵~这与“产物格子满时停止工作”的预期不一致喵~

## 2. 目标

当电动洗矿机的两个产物槽都被物品占用时，停止启动新的加工操作喵~

当任意一个产物槽为空时，恢复现有配方查找和加工流程喵~

机器不得因为输出槽满而消耗新的输入物品，也不得启动新的加工操作喵~

## 3. 范围

本次只修改 `ElectricDustWasher`，不修改普通洗矿机 `OreWasher`，也不修改 `AContainer` 或其他电动机器的通用行为喵~

本次不改变已经启动的加工操作喵~如果加工过程中产物槽才被填满，当前加工仍按现有流程完成；输出槽检查只阻止下一次加工启动喵~

本次规则不依赖随机产物种类，也不判断已有物品是否可以堆叠喵~只要两个输出槽都不是空槽，就视为产物槽已满喵~

## 4. 方案

在 `ElectricDustWasher.findNextRecipe(BlockMenu menu)` 进入配方遍历前调用现有的 `hasplusSlot(menu)` 喵~

如果 `hasplusSlot(menu)` 返回 `false`，立即返回 `null` 喵~这会让 `AContainer.tick(...)` 保持机器空闲，不会消耗输入或启动 `CraftingOperation` 喵~

如果存在空输出槽，则继续执行现有的输入匹配、随机产物生成和 `menu.fits(...)` 检查喵~现有 `menu.fits(...)` 继续保留，用于防御特殊物品实际无法插入输出槽的情况喵~

## 5. 数据流

1. `AContainer.tick(...)` 发现当前没有加工操作喵~
2. 调用 `ElectricDustWasher.findNextRecipe(...)` 喵~
3. 电动洗矿机先检查输出槽 `24、25` 是否至少有一个空槽喵~
4. 两个槽都被占用时返回 `null`，本次 tick 不做任何输入消耗喵~
5. 有空槽时继续匹配输入并生成随机产物喵~
6. 产物可以实际放入输出槽时消耗输入并启动加工喵~
7. 玩家取走任意输出槽物品后，后续 tick 自动重新尝试加工喵~

## 6. 边界与防御

空输出槽包括 `null` 和 Bukkit 的 AIR 物品喵~

两个输出槽都被占用时，即使物品堆叠数量未达到最大值，也必须暂停喵~

存在空输出槽但 `menu.fits(...)` 返回 `false` 时，不消耗输入并继续保持空闲喵~

本次不引入新的状态字段，因此机器暂停状态不需要额外持久化，也不会产生恢复状态不一致问题喵~

## 7. 验证计划

验证两个输出槽为空时，电动洗矿机能够正常启动加工喵~

验证一个输出槽有物品、另一个输出槽为空时，机器能够继续启动加工喵~

验证两个输出槽分别放置不同物品时，即使随机产物可以与其中一格堆叠，机器也不会消耗输入或启动新加工喵~

验证取走任意一个输出槽物品后，机器能够在后续 tick 自动恢复喵~

验证输出槽存在空位但产物无法通过 `menu.fits(...)` 时，输入物品仍然保留喵~

验证 `mvn package -DskipTests` 构建通过，并按项目要求执行 `copy_jars.bat` 喵~
