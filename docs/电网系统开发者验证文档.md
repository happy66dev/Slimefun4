# 粘液科技电网系统 — 开发者验证文档

> 最后更新：2026-05-23 | 验证用例：共 63 个

## 概述

电网系统的功能验证覆盖：连接规则（轴向模式）、路径计算、电力传输、冲突检测、BFS 缓存/DB 兜底、区块卸载自调度、连接器老化、电量计数器、限电器等。

## 验证规则速查

### validateConnection — 单向验证 + 轴向范围

| 发送方 | 接收方 | 正向 | 反向 | 结果 |
|---|---|---|---|---|
| CONNECTOR | CONNECTOR | `isWithinRangeAxial(loc1,loc2,range1)` | `true`(不验证) | 仅发送方范围 |
| CONNECTOR | GENERATOR | `isWithinRangeAxial(loc1,loc2,range1)` | `true` | ✅ |
| CONNECTOR | CONSUMER | `isWithinRangeAxial(loc1,loc2,range1)` | `true` | ✅ |
| CONNECTOR | CAPACITOR | `isWithinRangeAxial(loc1,loc2,range1)` | `true` | ✅ |
| GENERATOR | CONNECTOR | `true` | `isWithinRangeAxial(loc2,loc1,range2)` | ✅ |
| CAPACITOR | CONNECTOR | `isAdjacent` | `isWithinRangeAxial(loc2,loc1,range2)` | ✅ |
| CAPACITOR | CAPACITOR | `isAdjacent` | `isAdjacent` | 仅相邻 |
| 其他组合 | — | — | — | ❌ |

> `isWithinRangeAxial`：两个轴向差=0，第三个≤range且>0。
> 长途连接器特殊规则：`getNeighbors()` 中目标连接器需用**自身范围**反向覆盖长途连接器（完全隔离），两侧校验等价。

### checkRangeValidation — 成员收集

所有类型统一：`isWithinRangeAxial(connector, machine, connector.range)`

### getNeighbors — 路径预计算

| type | 搜索目标 | 范围/条件 | 验证 |
|---|---|---|---|
| GENERATOR | 所有连接器 | 无限制 | `validateConnection(G→C)` |
| GENERATOR | 调节器 | `getMaxConnectorRange()+RANGE` 轴向 | 调节器视为特殊连接器 |
| CAPACITOR | 相邻电容/连接器/调节器 | `isAdjacent`(6方向) | `validateConnection(C→C)` |
| CONNECTOR | 连接器 | 无限制 | 仅发送方轴向 |
| CONNECTOR | 发电机/用电器/电容/调节器 | `isWithinRangeAxial` | 各类型验证 |
| CONSUMER | — | — | 空(无出边) |

### 搜索方式统一

| 方法 | 方式 | 说明 |
|---|---|---|
| `processConnector` | 6轴向 × range | 成员收集 |
| `collectNetworkMembers` 调节器扩展 | 6轴向 × RANGE | 6×6=36 位置 |
| `findShortestPathsFromSource` | `getNeighbors` 图搜索 | 全部 `isWithinRangeAxial` |
| `validateConnection` | `isWithinRangeAxial` | 连接器全部轴向验证 |
| 电容↔连接器/调节器 | `isAdjacent` | 曼哈顿距离=1 |

## 关键方法调用链路

```
onMachinePlaced(newLoc)
  → removeHologramAt → isLocationInOtherGrid?
  → 遍历所有EnergyNet：调节器RANGE=6 + 连接器range范围
  → 找到匹配 → 新机器是调节器? 直接冲突 : markDirty

markDirty(l)
  → removeHologramAt + 全息清理（主线程短路）
  → regulator.equals(l)? destroyed=true + unregisterNetwork + cancelSelfTick
  → 否则 conflictMode=false + initialized=false + 直接submit initAsync

tick(block)  [显示层，无电力逻辑]
  → conflictMode? → 显示冲突返回
  → !initialized? → 提交initAsync
  → 有成员? → updateHologram(lastSupply, lastDemand)

tickSelf()  [逻辑层，BukkitScheduler异步自调度]
  → AtomicBoolean防重入 → destroyed/!initialized/conflictMode跳过
  → performEnergyTransfer → propagateToEnergyMeters
  → 统计 → chunk.isLoaded? runSync刷新全息 : 跳过

initializeNetworkAsync  [异步线程]
  → cancelSelfTick + pendingInit=false
  → synchronized(regulator)
  → clearNetworkData → collectNetworkMembers(缓存miss→DB兜底)
  → 冲突? → 标记对方conflictMode + return
  → precomputePaths(BFS父节点回溯+connector剪枝)
  → scheduleSelfTick + initialized=true
  → finally: 自愈重试 checked
```

## 关键标志位

| 标志 | 类型 | 作用 |
|---|---|---|
| `initialized` | volatile boolean | 电网是否已完成初始化 |
| `initializing` | volatile boolean | 正在初始化中 |
| `pendingInit` | volatile boolean | 已有初始化任务在队列，防重复提交 |
| `abortRequested` | volatile boolean | 请求打断当前初始化 |
| `destroyed` | volatile boolean | 电网已销毁 |
| `conflictMode` | volatile boolean | 冲突状态，tick/tickSelf 直接停工 |

## 调试参考

### 全息文字

| 全息文字 | 含义 |
|---|---|
| `初始化电网中 XX%` | 异步初始化进度 |
| `+X J ⚡` (绿) / `-X J ⚡` (红) | 发电盈余/缺口 |
| `等待接入设备` | 仅调节器，无其他成员 |
| `电网冲突：多个能源调节器相连` | 两个调节器互连 |
| `电网冲突：电网交叉` | 机器重叠，被标记 conflictMode |
| `找不到能源网络` | 调节器无成员 |

### 日志关键词

控制台搜 `[EnergyNet-DEBUG]`：
- `放置机器 ... -> 关联到电网` — 成功关联
- `collectNetworkMembers: 发现冲突调节器` — BFS 冲突
- `processConnector: 发现(DB) ...` — DB 兜底
- `tickSelf: 电力传输完成 ...` — 自调度传输统计
- `initializeNetworkAsync: 初始化被打断，自动重试` — 自愈重试
- `scheduleSelfTick/cancelSelfTick` — 自调度生命周期

### 常见问题

| 症状 | 可能原因 | 检查点 |
|---|---|---|
| 一直"初始化中" | 初始化被频繁打断 | 检查 `abortRequested` 日志 |
| 频繁"提交异步初始化" | `pendingInit` 未生效 | 检查任务开始时的清除逻辑 |
| 发电机不供电 | 路径计算失败 | `/sf grid` 查看路径，检查轴向范围 |
| 用电器不收电 | 不在连接器轴线上 | `isWithinRangeAxial` |
| 连接器不联通 | 轴向不够或不同轴 | 检查 `validateConnection` |
| 电容不工作 | 未与连接器相邻 | `isAdjacent`，对角线无效 |
| 一直"电网交叉" | 冲突源未移除 | 查附近重叠机器或等 `markDirty` |
| 关服报 `RejectedExecutionException` | ShutdownHook 被覆盖 | 检查钩子执行时机 |
