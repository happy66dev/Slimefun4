# 粘液科技电网系统 — 开发者验证文档

## 概述

本文档面向开发者，提供电网系统的功能验证方案，涵盖连接规则验证、路径计算验证、电力传输验证、边缘场景验证等。

---

## 验证环境准备

### 测试用连接器
| ID | 范围 |
|----|------|
| BASIC_ENERGY_CONNECTOR | 3 |
| ENERGY_CONNECTOR | 5 |
| POWERFUL_ENERGY_CONNECTOR | 4 |
| GILDED_ENERGY_CONNECTOR | 6 |
| REINFORCED_ENERGY_CONNECTOR | 10 |
| CARBONADO_ENERGY_CONNECTOR | 18 |

### 测试工具
- 管理员指令 `/sf grid` 查看当前看向的方块所属电网详细信息
- 能源调节器全息文字查看状态（含百分比进度）
- 控制台日志开启 `DEBUG = true`（EnergyNet.java顶部常量）
- `/sf grid` 对调节器显示电网概览，对发电机/用电器显示路由，对连接器显示范围+负载

## 验证用例

### TC-01：基础电网搭建

**目标**：验证最简电网能否正常工作

**步骤**：
1. 放置能源调节器
2. 在调节器相邻位置放置基础连接器（范围3）
3. 在连接器3格范围内放置1个发电机和1个用电器

**预期结果**：
- [ ] 调节器显示 "初始化电网中 XX%" → 完成后显示电力差额
- [ ] `/sf grid` 看向调节器显示：发电机1、用电器1、连接器1
- [ ] 发电机能正常供电给用电器
- [ ] 全息文字显示电力差额

### TC-02：连接器多级串联

**目标**：验证长距离电力传输

**步骤**：
1. 放置调节器
2. 放置碳金能源连接器(①，范围18)
3. 在①范围内放置基础连接器(②，范围3)，距离不超过3
4. 在②范围内放置发电机
5. 在①范围内（但不在②范围内）放置用电器

**预期结果**：
- [ ] 电网初始化成功
- [ ] 路径：发电机→②→①→用电器
- [ ] 电力正常传输

### TC-03：18格搜索（发电机找连接器）

**目标**：验证发电机通过碳金连接器远程接入

**步骤**：
1. 放置调节器
2. 放置碳金能源连接器（范围18）
3. 在连接器范围内（但非相邻）放置发电机，距离为15格
4. 在连接器范围内放置用电器

**预期结果**：
- [ ] 验证：`validateConnection(发电机, 连接器, GENERATOR, CONNECTOR)` 
  - 正向(发电机→连接器)：`forwardValid = true`（发电机无正向限制）
  - 反向(连接器→发电机)：`isWithinRange(连接器, 发电机, 18)` → true
  - 结果：✅ 连接有效
- [ ] 发电机被成功加入电网
- [ ] 路径计算正确

### TC-05：连接器间单向连接

**目标**：验证连接器间允许单向连接（高范围→低范围）

**步骤**：
1. 放置调节器
2. 放置基础连接器A（范围3）
3. 在距离A=3格处放置基础连接器B（范围3）
4. 在距离A=10格、距离B=3格处放置碳金连接器C（范围18）

**预期结果**：
- [ ] A↔B：距离3，范围3→3 ✅ 双向可连接
- [ ] C→B：C范围18覆盖B ✅
- [ ] 验证：`validateConnection(A, C, CONNECTOR, CONNECTOR)` 
  - 正向(A→C)：`isWithinRange(A, C, 3)` → false（距离10>3）❌
  - A无法发送到C，所以A→C不存在
- [ ] 验证：`validateConnection(C, B, CONNECTOR, CONNECTOR)`
  - 正向(C→B)：`isWithinRange(C, B, 18)` → true（距离3≤18）✅
  - 不检查反向 → ✅
  - C可以发送到B

### TC-11：路径预计算 — 最短路径选择

**目标**：验证多个路径中选择最短（BFS父节点回溯）

**步骤**：
1. 放置调节器
2. 布局：
   ```
   发电机 ← [①(范围3)] ←→ [②(范围3)]
      ↓                      ↓
    [③(范围3)] ←→ [④(范围3)]
      ↓
   用电器
   ```
   确保从发电机到用电器有两条路径：
   - 路径A：发电机→①→②→④→③→用电器（4个连接器）
   - 路径B：发电机→①→③→用电器（2个连接器）

**预期结果**：
- [ ] 路径B（长度2）被保留
- [ ] 路径A（长度4）被丢弃（非最短）
- [ ] 电力通过路径B传输

### TC-15：异步初始化打断 + pendingInit去重

**目标**：验证初始化途中放置新机器能打断并重开，且不会重复提交任务

**步骤**：
1. 放置调节器，触发初始化（撑大电网让初始化跑慢）
2. **在初始化完成前**快速放置新连接器
3. 观察控制台日志的 `tick` 调用次数

**预期结果**：
- [ ] 第一次初始化启动（`initializing = true, pendingInit = true`）
- [ ] 放置连接器 → `markDirty` → `initialized = false, abortRequested = true`
- [ ] 异步线程检测到 `abortRequested || destroyed` → 提前退出
- [ ] `initializing = false, abortRequested = false`
- [ ] 下个tick → `pendingInit = false` 可再次提交
- [ ] 控制台只出现**1条** "提交异步初始化任务"（而不是N条重复）

### TC-19：调节器在连接器链末端冲突

**目标**：验证超长连接器链末端放置调节器的即时冲突检测

**步骤**：
1. 建立一个200+连接器的长链电网
2. 在电网**最后一个连接器的范围外**再放连接器（不在电网内）
3. 在该连接器旁边放一个新的调节器

**预期结果**：
- [ ] 步骤2：新连接器不在电网范围内 → "未找到可关联电网"（正常）
- [ ] 步骤3：`onMachinePlaced` 扫描到附近有连接器（属于新连接器）
  - 新连接器未被占用，`isLocationInOtherGrid` 返回 false
  - 但如果新连接器和新调节器同时放置，都未被注册 → `getComponent` 可能返回 null
  - 但 `onMachinePlaced` 会扫描所有已注册电网的 `connectors` Map
  - 长链电网中有200+连接器 → 最近的连接器可能超出新调节器RANGE=6
  - 显示 "未找到可关联电网" ✅

### TC-25：conflictMode — 冲突时所有关联电网停工

**目标**：验证 BFS 发现冲突时，本电网和对方电网都停工显示冲突

**步骤**：
1. 建立电网 A（调节器 A + 连接器 + 发电机 + 用电器），等待正常初始化完成
2. 在电网 A 的任一连接器范围内放置**新的调节器 B**
3. 观察两个调节器的悬浮字

**预期结果**：
- [ ] 步骤 3：调节器 B 的 `onMachinePlaced` 触发 -> `collectNetworkMembers` BFS 发现机器被占用或调节器冲突
- [ ] `conflictMode = true` 被设置到本电网(调节器B的电网)
- [ ] `otherNet.conflictMode = true` 也被设置到对方电网(调节器A的电网)
- [ ] 调节器 A 悬浮字变为 `"&c电网冲突：电网交叉"`（原电力差额消失）
- [ ] 调节器 B 悬浮字也显示冲突信息

## 验证规则速查表

### validateConnection(loc1, loc2, type1, type2) — 单向验证

| type1(发送方) | type2(接收方) | 正向(type1→type2) | 反向(type2→type1) | 结果 |
|---------------|---------------|-------------------|-------------------|------|
| CONNECTOR | CONNECTOR | `isWithinRange(loc1,loc2,range1)` | `true`(不验证) | 仅发送方范围 |
| CONNECTOR | GENERATOR | `isWithinRange(loc1,loc2,range1)` | `true` | 连接器覆盖发电机 |
| CONNECTOR | CONSUMER | `isWithinRange(loc1,loc2,range1)` | `true` | 连接器覆盖用电器 |
| CONNECTOR | CAPACITOR | `isWithinRange(loc1,loc2,range1)` | `true` | 连接器覆盖电容 |
| GENERATOR | CONNECTOR | `true` | `isWithinRange(loc2,loc1,range2)` | 连接器覆盖发电机 |
| CAPACITOR | CONNECTOR | `isAdjacent(loc1,loc2)` | `isWithinRange(loc2,loc1,range2)` | 相邻+连接器覆盖 |
| CAPACITOR | CAPACITOR | `isAdjacent(loc1,loc2)` | `isAdjacent(loc2,loc1)` | 相邻（特例） |
| CAPACITOR | GENERATOR | — | — | ❌ 无效 |
| CAPACITOR | CONSUMER | — | — | ❌ 无效 |
| CONSUMER | 任何 | — | — | ❌ 无效 |
| GENERATOR | GENERATOR | — | — | ❌ 无效 |
| GENERATOR | CONSUMER | — | — | ❌ 无效 |
| GENERATOR | CAPACITOR | — | — | ❌ 无效 |

### checkRangeValidation(connectorLoc, machineLoc, machineType) — 成员收集验证

所有类型统一验证：`isWithinRange(connector, machine, connector.range)`，不再区分 machineType。

### getNeighbors — 路径预计算邻居搜索

| type | 搜索目标 | 搜索范围 | 验证 |
|------|----------|----------|------|
| GENERATOR | 所有连接器 | 无限制 | `validateConnection(GENERATOR→CONNECTOR)` |
| GENERATOR | 调节器 | `getMaxConnectorRange()` + RANGE | 调节器视为特殊连接器 |
| CAPACITOR | 相邻电容 | isAdjacent | 直接添加 |
| CAPACITOR | 相邻连接器 | isAdjacent | `validateConnection(CAPACITOR→CONNECTOR)` |
| CONNECTOR | 其他连接器 | 无限制 | `validateConnection(CONNECTOR↔CONNECTOR)`（仅发送方） |
| CONNECTOR | 发电机 | `isWithinRange(connector, generator, connRange)` | `validateConnection(CONNECTOR→GENERATOR)` |
| CONNECTOR | 用电器 | `isWithinRange(connector, consumer, connRange)` | `validateConnection(CONNECTOR→CONSUMER)` |
| CONNECTOR | 电容 | `isWithinRange(connector, capacitor, connRange)` | `validateConnection(CONNECTOR→CAPACITOR)` |
| CONNECTOR | 调节器 | `isWithinRange(connector, regulator, connRange)` | 直接添加 |
| CONSUMER | — | — | 空集合（无出边） |

### BFS 搜索范围（6轴向 vs 正方体）

| 方法 | 搜索方式 | 计算公式 |
|------|----------|----------|
| `processConnector` | 6轴向 × range | `6 × range` 个位置 |
| `collectNetworkMembers` 调节器扩展 | 6轴向 × RANGE | `6 × 6 = 36` 个位置 |
| `findShortestPathsFromSource` | 通过 `getNeighbors` 图搜索 | 无位置枚举，直接查内存集合 |

## 关键方法调用链路（最终版）

```
onMachinePlaced(newMachineLoc)  [静态]
  → removeHologramAt(newMachineLoc)        // 清除旧悬浮字
  → isLocationInOtherGrid(newMachineLoc)?  // 冲突检测
  → 遍历所有已注册EnergyNet实例:
      → 检查调节器 RANGE=6 范围内
      → 检查所有连接器的 range 范围内
  → 找到最佳匹配电网:
      if (新机器是调节器) → 直接显示冲突 + return
      else → bestNetwork.markDirty(newMachineLoc)

markDirty(l)
  → removeHologramAt(l)
  if (调节器被拆):
    → destroyed = true, abortRequested = true
    → removeAllHolograms()
    → manager.unregisterNetwork(this)
  else:
    → conflictMode = false               // 重置冲突模式
    → initialized = false, abortRequested = true

tick(block, blockData)  [主线程]
  → conflictMode? → updateHologram("电网冲突：电网交叉") + return  // 立即停工
  → !initialized?
    → !initializing && !pendingInit? → GRID_EXECUTOR.submit(initAsync)
    → pendingInit = true
    → return
  → initialized && 有成员? → performEnergyTransfer + updateHologram

initializeNetworkAsync  [异步线程]
  → pendingInit = false
  → bfsDbQueryCount.set(0)               // 重置DB查询计数器
  → synchronized(regulator)
  → destroyed? → 退出
  → initializing = true
  → clearNetworkData()
  → abortRequested || destroyed? → 退出
  → collectNetworkMembers()              // 缓存miss时→querySlimefunItemFromDb兜底
      → 调节器6轴向扩展RANGE格 → 缓存miss? → DB查询（每10次sleep 1ms）
      → BFS: processConnector() → 缓存miss? → DB查询（每10次sleep 1ms）
      → 发现冲突？→ 标记对方电网conflictMode = true + 返回false
      → BFS: processCapacitor() → 相邻电容
      → 每20步更新一次全息进度（0%~70%）
  → abortRequested || destroyed? → 退出
  → collectResult == false? → conflictMode = true + return  // 进入冲突模式
  → precomputePaths()
      → findShortestPathsFromSource(每个generator)
          → ArrayList + head 指针（父节点回溯，无路径克隆）
          → pathContainsNode 回溯去环
          → connectorShortest 连接器剪枝
          → 每50步更新一次全息进度（70%~100%）
      → findShortestPathsFromSource(每个capacitor)
  → abortRequested || destroyed? → 退出
  → initialized = true
  → !destroyed? → runSync: updateHologram(电力差额)

ShutdownHook [JVM关闭时]
  → GRID_EXECUTOR.shutdown()
  → awaitTermination(5秒)
  → 超时? → shutdownNow()
```

## 性能指标

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| BFS 内存分配 | O(分支数 × 路径长) Map/List克隆 | O(节点数) 无克隆 |
| 去环复杂度 | `List.contains()` O(n) | 回溯父链 O(n) 零对象分配 |
| 连接器重复探索 | 反复探索 | `connectorShortest` 剪枝跳过 |
| 进度反馈 | 无 | 0%-70%-100% 动态显示 |
| 调节器被拆 | 异步线程可能继续操作已销毁电网 | `destroyed` 直接拦截 |
| 异步任务提交 | tick 每刻提交一次 → 无限堆积 | `pendingInit` 去重 → 最多一个等待 |
| 关服 | 守护线程被 JVM 强杀 | ShutdownHook 优雅终止最多等5秒 |
| 冲突恢复 | 无机制，永久卡死 | `conflictMode` 停工 + `markDirty` 事件驱动恢复 |
| 冲突影响范围 | 仅新初始化的电网停工 | **所有关联电网**停工显示交叉 |
| 区块未加载的机器 | BFS 直接跳过，永不被发现 | `getComponent` 缓存 miss → `querySlimefunItemFromDb` 数据库兜底（每10次sleep 1ms限速） |

## 关键标志位一览

| 标志 | 类型 | 作用 |
|------|------|------|
| `initialized` | volatile boolean | 电网初始化是否完成 |
| `initializing` | volatile boolean | 电网正在初始化中 |
| `pendingInit` | volatile boolean | 已有异步任务在队列中等待，防重复提交 |
| `abortRequested` | volatile boolean | 请求打断当前初始化，异步线程检查点退出 |
| `destroyed` | volatile boolean | 电网已销毁，异步线程不再执行任何操作 |
| `conflictMode` | volatile boolean | 电网处于冲突状态，tick 直接停工不传输电力 |

### 常见调试问题

| 症状 | 可能原因 | 检查点 |
|------|----------|--------|
| 电网一直"初始化中 XX%" | 初始化被反复打断 | 检查是否有机器频繁放置/拆除，查看 `abortRequested` 日志 |
| "提交异步初始化任务" 频繁出现 | `pendingInit` 未生效 | 检查 `pendingInit` 是否在任务开始时被清除 |
| 发电机不供电 | 路径计算失败 | 检查连接器范围是否覆盖发电机，`/sf grid` 查看路径 |
| 用电器不收电 | 用电器在连接器范围外 | 检查 `isWithinRange(connector, consumer, range)` |
| 连接器不联通 | 发送方范围不够 | 检查发送方连接器的 range，**不再要求反向覆盖** |
| 电容不工作 | 电容未与连接器相邻 | 检查 `isAdjacent(capacitor, connector)` |
| 调节器显示"电网交叉"但附近没有冲突 | 其他电网标记了本电网为冲突 | 用 `/sf grid` 查看本电网和附近电网，找重叠机器 |
| 调节器一直"电网交叉"不恢复 | 冲突源未被移除 | 检查附近是否有其他电网的重叠机器，或等待 `markDirty` 触发 |
| 关服时报 `RejectedExecutionException` | ShutdownHook 被关服流程覆盖 | 检查 ShutdownHook 的执行时机，考虑加回 `daemon=true` |
